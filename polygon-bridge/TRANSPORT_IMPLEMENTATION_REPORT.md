## 구현과 기준선
기준선에서 Node 검사 중 06의 가벼운 시험이 실패했다. 기본 레일이 연결되지 않은 상태에서 시험을 시작해 작업자가 첫 틈에 떨어졌다. 06은 레일을 연결한 상태에서 시작하고 학생이 다시 조정할 수 있다. 작업자 시험 뒤 한 번 눌러 같은 설계로 화물차를 보낼 수 있다. 화물차의 앞뒤 바퀴와 작업자의 발이 실제 상판을 지지점으로 사용한다. 05의 기존 잔상·경첩 드래그·두 번 터치·두 대각선 보강을 유지했다.

## Node 시나리오

| 단계 | 완주·비교 결과 | 실패 관찰 |
|---|---|---|
| 01 | 근접한 레일 보정 후 도착 | 레일 좁아짐·벌어짐에서 안내 바퀴 정지 |
| 02 | 비스듬한 평행 레일로 도착 | 수평 또는 반대 경사의 아래 레일에서 낙하 |
| 03 | 90° 수납 후 통과 | 45°에서 통로 차단, 97°·103°·110°에서 벽 접촉 |
| 04 | 다리와 문을 지나 도착 | 다리만 완성하면 문에 막힘, 문만 열면 낙하 |
| 05 | AC와 BD 모두 도착 | 무보강 및 기존 변 중복 보강에서 낙하 |
| 06 | 무보강 작업자 통과, 대각선 보강 화물 도착 | 무보강 화물 낙하. 하중에 따른 최대 전단 변위 차이 확인 |
| 07 | 발판을 타고 강둑에 도착 | 짧은 링크에서 낙하, 다른 링크에서 미도킹 정지 |
| 08 | 화물차가 네 장치를 거쳐 도착 | 레일 오류·문 덜 수납·과수납·무보강·불량 링크·도킹 틈 확대를 개별 재현 |
| 09 | 두 발사대가 차례로 펴져 도착 | 하나만 맞추면 해당 미완성 상판에서 낙하 |
| 10 | 긴 문을 좁은 홈에 넣어 통과 | 덜 접으면 통로 차단, 과수납하면 벽에 닿아 정지 |
| 11 | 양쪽에 각각 한 대각선을 설치해 도착 | 한쪽만 보강하거나 같은 쪽에 두 막대를 몰면 낙하 |
| 12 | 다른 높이의 강둑에 정지각을 맞춰 도착 | 링크가 짧으면 낙하, 정지 위치가 어긋나면 도킹 실패 |

`node polygon-bridge/transport-regression.cjs`로 재현한다. 테스트에는 스냅 유지·해제, 물리 도킹 8·10·12 월드 픽셀, 포인터 취소, 50% 축소 터치 좌표, 09의 30·60·120Hz 시간 분할 비교가 포함된다. 30Hz 분할 시험은 기기에서 측정한 프레임 속도를 뜻하지 않는다.

## 파일과 실행 경로
- `transport.html`에 02~12 단계, 두 하중 시험, 독립 레일과 프레임, 두께를 가진 차단문, 정지 위치 조정 승강교를 구현했다.
- `index.html`의 물리 챕터 링크 문구를 12단계로 수정했다. 기존 조건형 게임 로직과 기록 형식은 유지했다. 01의 경로는 `telescopic-bridge.html`, 나머지는 `transport.html#2`~`#12`다.
- `transport-regression.cjs`, `transport-browser.py`, `.github/workflows/transport-browser.yml`은 물리·브라우저 검수에 사용한다.
- `DESIGN_SPEC.md`, `TRANSPORT_STAGE05_REVIEW.md`에 현재 구현과 검수 범위를 추가했다.

## 물리 측정값
06단계의 동일한 레일에서 작업자·무보강 최대 수평 변위는 8.56 월드 픽셀이었다. 화물차·무보강과 화물차·기존 변 중복은 모두 80.01에서 낙하했고, 화물차·AC 보강은 0.01 미만으로 유지되어 도착했다. 0.25° 간격으로 실제 통과를 측정한 각도 범위는 03에서 87.5~91.5°, 10에서 89.5~90.5°였다. 좁은 수납실에서는 문 길이와 두께가 허용 각도를 줄인다.
